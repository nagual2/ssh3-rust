| **The client configuration of ssh(1)** — the `-N` flag holds the connection open for the forwards without opening a session; the `-F` flag names another `ssh_config` file, and a file that cannot be read is ignored with a warning on the standard error, like the Go implementation does. The `-o` option accepts the `LocalForward`, `RemoteForward`, `DynamicForward`, `ProxyJump` and `ServerAliveInterval` keywords next to the ones it already knew, and the ssh_config file understands the `Include` directive (recursive, with glob patterns, a cycle guard and a depth limit of 16) and the `Match` blocks with the `all`, `final`, `host`, `originalhost`, `user`, `localuser` and `exec` criteria and the `!` negation. ### Fixed / Исправлено / Behoben

| English | Русский | Deutsch |
|---------|---------|---------|
| **The server closes the channel after the exit status.** The Go reference waits for the status to be sent before the deferred close of the channel, and a client that reads the end of the stream before the status reports a failure. The Rust server now sends the status, gives the QUIC stream a moment to flush it, and closes the channel; the cross-implementation scenarios pass against the Go tags v0.1.12 and v0.1.37 alike. | **Сервер закрывает канал после exit-status.** Go-эталон дожидается отправки статуса перед отложенным закрытием канала, а клиент, прочитавший конец потока раньше статуса, сообщает об ошибке. Rust-сервер теперь отправляет статус, даёт потоку QUIC время на flush и закрывает канал; кросс-имплементационные сценарии проходят против тегов Go v0.1.12 и v0.1.37 одинаково. | **Der Server schließt den Kanal nach dem Exit-Status.** Die Go-Referenz wartet mit dem Senden des Status, bis der aufgeschobene Close des Kanals erfolgt, und ein Client, der das Ende des Stroms vor dem Status liest, meldet einen Fehler. Der Rust-Server sendet den Status nun, gibt dem QUIC-Strom einen Moment zum Flush und schließt den Kanal; die Cross-Implementation-Szenarien bestehen gegen die Go-Tags v0.1.12 und v0.1.37 gleichermaßen. |
| **The client no longer announces the HTTP/3 datagram support.** A peer that sees the announcement (SETTINGS_H3_DATAGRAM, 0x33) opens a second reader on the shared QUIC datagram queue and takes the SSH3 datagrams away. The Rust side keeps the datagrams of the protocol for itself; the regression test reads the settings from the QUIC level. | **Клиент больше не анонсирует поддержку HTTP/3-датаграмм.** Пир, увидевший анонс (SETTINGS_H3_DATAGRAM, 0x33), поднимает второго читателя на общей очереди датаграмм QUIC и забирает датаграммы SSH3. Rust-сторона оставляет датаграммы протокола себе; регресс-тест читает настройки на уровне QUIC. | **Der Client meldet die HTTP/3-Datagrammunterstützung nicht mehr an.** Ein Peer, der die Anzeige sieht (SETTINGS_H3_DATAGRAM, 0x33), öffnet einen zweiten Leser auf der gemeinsamen QUIC-Datagrammwarteschlange und nimmt die SSH3-Datagramme weg. Die Rust-Seite behält die Datagramme des Protokolls für sich; der Regressionstest liest die Einstellungen auf QUIC-Ebene. |
| **The interop harness resolves the Go peers through `SSH3_GO_REPO`.** The Go checkout is no longer looked up relative to the workspace root, so the scenarios work from this standalone repository. When the checkout or the Go toolchain is missing, every interop scenario is **skipped** with a `skipping:` line in the test log instead of failing the suite; a scenario never reports success without having exercised the wire. | **Interop-харнесс находит Go-пиров через `SSH3_GO_REPO`.** Checkout Go-репозитория больше не ищется относительно корня воркспейса, поэтому сценарии работают из этого самостоятельного репозитория. Если checkout или тулчейн Go недоступны, каждый interop-сценарий **пропускается** со строкой `skipping:` в логе тестов вместо падения набора; сценарий никогда не сообщает об успехе, не пройдя по проводу. | **Die Interop-Testvorrichtung findet die Go-Peers über `SSH3_GO_REPO`.** Der Go-Checkout wird nicht mehr relativ zur Wurzel des Workspace gesucht, die Szenarien laufen daher aus diesem eigenständigen Repository. Fehlen der Checkout oder die Go-Toolchain, wird jedes Interop-Szenario mit einer `skipping:`-Zeile im Testprotokoll **übersprungen**, statt die Suite fehlschlagen zu lassen; ein Szenario meldet nie Erfolg, ohne den Draht benutzt zu haben. |
| **The interop scenarios no longer collide on the agent socket path.** The Rust server derives that path from the process id and a timestamp, so two concurrent scenarios could compute the same path and the loser's cleanup removed the winner's socket. The scenarios that open a Rust-server agent socket now run one after another. | **Interop-сценарии больше не сталкиваются за путь сокета агента.** Rust-сервер выводит этот путь из pid и метки времени, поэтому два параллельных сценария могли вычислить одинаковый путь, и очистка проигравшего удаляла сокет победителя. Сценарии, открывающие сокет агента Rust-сервера, теперь выполняются по очереди. | **Die Interop-Szenarien kollidieren nicht mehr um den Pfad des Agent-Sockets.** Der Rust-Server leitet ihn aus Prozesskennung und Zeitstempel ab, zwei parallele Szenarien konnten denselben Pfad berechnen und die Aufräumaktion des Verlierers löschte den Socket des Gewinners. Die Szenarien, die einen Agent-Socket des Rust-Servers öffnen, laufen nun nacheinander. |
