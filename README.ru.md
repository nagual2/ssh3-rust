# SSH3 поверх HTTP/3 — реализация на Rust

[![License: Apache-2.0](https://img.shields.io/badge/License-Apache_2.0-blue.svg)](https://www.apache.org/licenses/LICENSE-2.0)
[![Rust](https://img.shields.io/badge/rust-1.85%2B-orange.svg)](https://www.rust-lang.org)
[![Status: active](https://img.shields.io/badge/status-active-brightgreen.svg)](FROZEN.md)

[English](README.md) | **Русский** | [Deutsch](README.de.md)

SSH3 переносит семантику удалённых сессий в духе RFC 4254 на QUIC, TLS 1.3 и
HTTP/3 Extended CONNECT. Протокол сохраняет привычный SSH-сценарий — shell-сессии,
exec, выделение PTY, изменение размера окна, пересылку сигналов, прямую
TCP/UDP-пересылку портов, пересылку SSH-агента — и переносит его на
HTTP-нативный транспорт с QUIC-нативными датаграммами.

В этом репозитории находится **только реализация на Rust** — независимая
референс-реализация протокола SSH3.

> [!NOTE]
> SSH3 всё ещё экспериментальный, и имя протокола может измениться. Протокол
> сохраняет семантику сессий и каналов в стиле SSH поверх QUIC и HTTP/3
> Extended CONNECT.

> [!WARNING]
> **Этот workspace был заморожен (dormant) с 2026-10-13 по 2026-10-22; 2026-10-22
> владелец снял заморозку** с целью довести реализацию до паритета с
> Go-реализацией ([nagual2/ssh3-go](https://github.com/nagual2/ssh3-go)).
> Единственный поставляемый продукт — по-прежнему Go-реализация: этот
> репозиторий не входит ни в один релиз-артефакт, а свежий аудит всё ещё
> требуется до первого. См. [`FROZEN.md`](FROZEN.md) и [`ROADMAP.md`](ROADMAP.md).

## Позиционирование

> Независимая референс-реализация протокола SSH3 на Rust. Wire-совместима с
> [francoismichel/ssh3](https://github.com/francoismichel/ssh3) и с
> [nagual2/ssh3-go](https://github.com/nagual2/ssh3-go), но **не является их
> форком и не заменяет их**.

Этот репозиторий — **второй стек** и **эталон протокола** в семействе
реализаций SSH3. Его задача — сохранить живое второе, независимое прочтение
wire-формата, служить базой для C-порта
([nagual2/ssh3-c](https://github.com/nagual2/ssh3-c)) и дать протоколу
проверяемую, аудируемую реализацию, не привязанную к продуктовой поверхности
Go-версии.

| Требование | Примечания |
| --- | --- |

| Go toolchain (1.21+) | **Только** для кросс-имплементационных interop-тестов. Для сборки, запуска и тестирования самого Rust-кода не нужен. |
| Unix-подобная ОС | Interop-сценарии компилируются только на Unix (`#[cfg(unix)]`); остальной workspace собирается и на Windows. |

## Сборка и запуск

```bash
git clone https://github.com/nagual2/ssh3-rust.git
cd ssh3-rust
cargo build --workspace
```

Workspace даёт два бинарника:

| Бинарник | Пакет | Назначение |
| --- | --- | --- |
| `ssh3-rust-client` | `ssh3-client` | Клиент SSH3: shell, exec, PTY, аутентификация, форвардинг. |
| `ssh3-rust-server` | `ssh3-server` | Сервер SSH3: сессии, PTY, аутентификация, форвардинг. |

Имена пакетов остаются `ssh3-client` / `ssh3-server` — они описывают протокол,
а не продукт; бинарники несут имя продукта, чтобы никогда не конфликтовать с
Go-реализацией в `PATH`.

Справка по обоим бинарникам прямо из workspace:

```bash
cargo run -p ssh3-client -- --help
cargo run -p ssh3-server -- --help
```

Для секретов предпочитайте файловые флаги (`--password-file`,
`--bearer-token-file`, `--oidc-client-secret-file`) передаче секретов в
командной строке: значения в `argv` утекают через историю shell, список
процессов и CI-логи.

## Быстрый старт

Rust-сервер стартует с самоподписанным сертификатом, поэтому в примерах ниже
используется `--insecure` (вместо этого закрепляйте сертификат через
`--ca-cert`, если пир находится не на той же машине).

Запуск локального сервера:

```bash
cargo run -p ssh3-server -- \
  --bind 127.0.0.1:4433 \
  --user "$USER" \
  --require-auth \
  --authorized-identity ~/.ssh/authorized_keys
```

Подключение закрытым ключом и открытие shell:

```bash
cargo run -p ssh3-client -- \
  --insecure \
  --user "$USER" \
  --identity ~/.ssh/id_ed25519 \
  https://127.0.0.1:4433/ssh3-term
```

Запуск удалённой команды вместо запроса shell:

```bash
cargo run -p ssh3-client -- \
  --insecure \
  --user "$USER" \
  --identity ~/.ssh/id_ed25519 \
  https://127.0.0.1:4433/ssh3-term \
  -- "printf 'hello from ssh3\n'"
```

Сервер сейчас принимает любой URL-путь — поддержки секретного пути пока нет
(см. раздел с ограничениями).

## Крейты workspace

| Крейт | Описание |
| --- | --- |
| `ssh3-proto` | Wire-формат: типы сообщений, SSH-строки и varint, кодирование и разбор SSH3-фрейминга. |
| `ssh3-core` | Рантайм конверсаций и каналов: жизненный цикл канала, потоки данных и extended-data, очереди датаграмм. |
| `ssh3-quinn` | Привязки QUIC-транспорта к `quinn`, конфигурация TLS и генерация самоподписанных сертификатов. |
| `ssh3-h3` | Bootstrap HTTP/3 и обработка Extended CONNECT (`:protocol=ssh3`), включая путь диспетчеризации датаграмм. |
| `ssh3-auth` | Помощники аутентификации: открытый ключ (ed25519, P-256, RSA), поддержка password-verifier и проверка OIDC-токенов. |
| `ssh3-client` | Рантайм и CLI-бинарник клиента: установка сессии, PTY, resize, сигналы, агент и пересылка портов. |
| `ssh3-server` | Рантайм и CLI-бинарник сервера: аутентификация, обработка сессий, PTY, форвардинг. |

`vendor/h3` — намеренный шим `[patch.crates-io]` поверх crates.io-крейта
`h3` 0.0.8. Он добавляет поддержку псевдо-заголовка `:protocol`, нужную
Extended CONNECT и отсутствующую в upstream `h3`. Не заменяйте его
upstream-крейтом — см. [`CONTRIBUTING.md`](CONTRIBUTING.md).

### Кросс-имплементационная (interop) матрица

22 сценария прогоняют **настоящие Go-бинарники**, собранные из репозитория
[nagual2/ssh3-go](https://github.com/nagual2/ssh3-go), против Rust-реализации
в обе стороны:

| Сценарий | Rust → Go | Go → Rust |
| --- | --- | --- |
| exec (удалённая команда) | да | да |
| Аутентификация открытым ключом (ed25519, P-256, RSA, согласование дополнительных алгоритмов) | да | да |
| Аутентификация по паролю | да | да |
| Аутентификация OIDC (токен и интерактивный вход) | да | да |
| Shell с PTY | да | да |
| Изменение размера окна (SIGWINCH) | — | да |
| Пересылка сигналов | — | да |
| Прямая TCP-пересылка | да | да |
| Прямая UDP-пересылка (датаграммы) | да | да |
| Аутентификация через SSH-агент и пересылка агента | да | да |

> [!WARNING]
> Interop-тестам нужен **чекаут Go-репозитория** и **Go toolchain**.
> Переменная окружения `SSH3_GO_REPO` указывает на этот чекаут: харнесс
> собирает из него Go-первоисточники и прогоняет против них сценарии. Без неё
> (или без Go toolchain) каждый interop-сценарий **пропускается** — в лог тестов
> уходит строка `skipping:` — вместо падения. Закрепляйте чекаут на теге
> релиза Go-реализации: interop-матрица проверяется против конкретного релиза
> Go, а не против `main` (см. `M0.C.2` в [`ROADMAP.md`](ROADMAP.md)). Замороженный
> shim `h3` 0.0.8 совместим с Go-реализацией до линейки `quic-go` v0.40.x;
> чекаут с более новым `quic-go` (v0.49+) на уровне wire несовместим с этим
> воркспейсом — сценарии падают с HTTP/3-ошибкой `0x104`. Сценарии
> компилируются только на Unix-подобных хостах.

## Совместимость с Go-реализацией

Rust-реализация говорит на том же wire-протоколе, что и Go-реализация: те же
нумерация сообщений, обрамление, потоки аутентификации и заголовки
форвардинга. Interop-матрица выше — регрессионная защита этого утверждения:
изменение в одной из реализаций, ломающее другую, валит тесты Rust-реализации.

По продуктовой поверхности Go-реализация впереди. Это поставляемый продукт,
а Rust-workspace не ставит себе задачу его повторять:

| Возможность | Go-реализация | Rust-workspace |
| --- | --- | --- |
| Shell-сессия и exec | да | да |
| PTY, resize, пересылка сигналов | да | да |
| Аутентификация по ключу, паролю, OIDC, через агента | да | да |
| Прямая TCP/UDP-пересылка | да | да (рантайм и CLI) |
| Обратная пересылка (`-R`), динамический SOCKS (`-D`), proxy jump | да | нет |
| Control master / мультиплексирование соединений | да | нет |
| Передача файлов (`-transfer`) | да | нет |
| Секретный URL-путь | да | нет |
| Публичные сертификаты (Let's Encrypt) | да | нет (только самоподписанные) |
| Релизная упаковка (`.deb`, systemd-юнит, goreleaser) | да | нет |

## Известные ограничения и аудиторские находки

Workspace заморожен со следующими открытыми пунктами. Они перечислены здесь,
чтобы никто не принял этот код за production-hardened.

| Находка | Severity | Место | Описание |
| --- | --- | --- | --- |
| F-16 | Low (pre-auth) | `ssh3-server/src/lib.rs:344-393` | При парольной аутентификации вычисленный хэш сравнивается оператором `==` с коротким замыканием вместо constant-time сравнения; блокировка после серии неудач отсутствует. |
| F-19 (остаток Rust-клиента) | Medium | `ssh3-client/src/lib.rs:1406-1411` | Битая датаграмма по-прежнему обрывает приём датаграмм в Rust-клиенте. Go-часть F-19 исправлена в Go-репозитории; остаток в Rust не исправлен. |
| F-20 | Medium | `ssh3-core/src/conversation.rs:292` | Нет бюджета каналов: `dangling_datagram_queues` — неограниченный `HashMap` по идентификатору, заданному пиром. |
| Нет лимита длины SSH-строки | High | `ssh3-proto/src/wire.rs:167` | `read_ssh_bytes` выделяет буфер по длине из peer-varint. Go-реализация ограничивает длину (`util.MaxSSHStringLen = 1<<24`); Rust — нет. |
| `max_packet_size` не клампится | High | `ssh3-quinn/src/channel.rs:364`, `ssh3-core/src/channel.rs:447` | Объявленное пиром значение принимается как есть: его не клампят к локальному максимуму и не поднимают до разумного минимума. |
| Нет `permit-open` / `permit-listen` | High | `ssh3-server/src/lib.rs:1718` | Сервер пересылает на любой адрес, который запросит пир; политики форвардинга, ограничивающей это, нет. |
| Устаревшая зависимость QUIC | Medium | `Cargo.lock` (`quinn-proto` 0.11.14) | RUSTSEC-2026-0185 (удалённое истощение памяти) и обход лимита DATAGRAM. Исправлено в `quinn-proto` 0.11.19+. Путь DATAGRAM — ядро SSH3, поэтому advisory применим к самому протоколу. |
| Минимальный сервер | — | `ssh3-server` | Только самоподписанные сертификаты, нет автоматизации публичных сертификатов, нет секретного URL-пути. |

Воркспейс собирается в `.github/workflows/ci.yml`: `cargo fmt --check`, clippy с
`-D warnings`, набор тестов и interop-матрица против закреплённого Go-релиза
`v0.1.12`. Тулчейн закреплён в `rust-toolchain.toml`, форматтер и линтер
настроены в `rustfmt.toml` и `clippy.toml`.

Кроме того, у парсера wire-формата есть вторая, асинхронная копия в
`ssh3-core/src/channel.rs:439-615`; round-trip-тесты проверяют
`ssh3_proto::Ssh3Message::parse`, который не используется в боевом пути.

## Спецификация wire-формата

Протокол, который здесь реализован, — экспериментальный черновик IETF
`draft-michel-remote-terminal-http3-00` (pre-standard). Конкретная кодировка,
которую используют реализации — раскладка сообщений, кодирование строк,
заголовки форвардинга — описана в репозитории C-порта:
[SSH3 wire protocol, rev nagual2/1](https://github.com/nagual2/ssh3-c/blob/main/docs/SPEC-wire.md).
