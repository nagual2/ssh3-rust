# ROADMAP — SSH3-Rust: развитие отдельного проекта

**Статус:** заморожен (dormant) с 2026-10-13 · **Решение владельца:** выделить в самостоятельный проект с отдельным репозиторием на GitHub
**Дата составления:** 2026-10-21 · **Основание:** ревью кода Rust-реализации (15 537 строк src, 7 крейтов) и проверка GitHub

---

## 1. Решение в одном абзаце

Код **дописывать, не переписывать**: wire-формат построчно совпадает с рабочей Go-реализацией, 22 interop-теста доказывают совместимость с реальными бинарниками, прикладной слой содержит ноль прод-`unwrap`/`panic`. Переписывание выбросило бы проверенную базу ради повторения 15k строк и новой отладки совместимости. При этом «дописать всё до уровня Go-продукта» — нерентабельно: разрыв ~30 клиентских и ~20 серверных фич, а Go-версия вылизана за 200+ коммитов аудитов. **Цель Rust-проекта — не замена Go, а второй стек / эталон протокола / база для C-порта `ssh3-c`.** Разморозка возможна только после ребрендинга (M0), закрытия дыр (M2), починки инфраструктуры (M3–M4) и свежего аудита (M7.1).

## 5. Дорожная карта

### M0 — Глубокий ребрендинг (фундамент идентичности проекта)

**Зачем первым.** Сегодня код носит идентичность Go-форка: имена крейтов и бинарников, README «о двух реализациях», ссылки на `crates/`, унаследованный `Plan.md` про Go-фичи, отсутствие метаданных. Если вынести это как есть — новый репозиторий будет выглядеть копией чужого продукта, а `ssh3-server` ещё и **конфликтует по имени с Go-сервером в `/usr/bin`**. Все правки M1+ вносились бы в чужой нейминг. Ребрендинг идёт до изоляции, но выполняется в её рамках: M0 задаёт идентичность, M1 выносит её в отдельный репозиторий.

#### M0.D — Позиционирование (текст для README)

> **SSH3-Rust** — независимая референс-реализация протокола SSH3 на Rust: QUIC + TLS 1.3 + HTTP/3 Extended CONNECT, SSH-подобная семантика сессий и каналов. Wire-совместима с [francoismichel/ssh3](https://github.com/francoismichel/ssh3) и форком [nagual2/ssh3-go](https://github.com/nagual2/ssh3-go), но **не является их форком и не заменяет их**. Экспериментальный протокол: IETF draft-michel-remote-terminal-http3-00, статус — pre-standard. Референс-реализация Go-версии остаётся единственным поставляемым продуктом; этот репозиторий развивается как второй стек и как эталон протокола.

#### M0.E — Риски ребрендинга

| № | Риск | Митигация |
|---|------|-----------|
| 1 | Массовые правки в коде (префикс типов, разбиение модулей) ломают сборку | Делать атомарно: каждый шаг — отдельный коммит с зелёными тестами |
| 2 | «Косметика без смысла» — переименования без сближения с назначением | Одновременно с ребрендингом закрывать M2 (реальные дыры), иначе правки не окупятся |
| 3 | Переименование бинарников ломает скрипты пользователей Go-версии | Явно задокументировать в `README` и в release notes; старые имена не оставлять |
| 4 | Рассинхрон interop-тестов с Go-версией | Закрепить тег Go-репо (M0.C.2) |
| 5 | Потеря связи с исходным форком при переезде | `git subtree split` сохраняет авторство; `NOTICE` фиксирует происхождение (M0.A.7) |

### M2 — Безопасность (блокер разморозки)

| № | Задача | Файлы | Серьёзность | Критерий приёмки |
|---|--------|-------|-------------|-----------------|
| 1.1 | **Лимит длины SSH-строки**: `read_ssh_bytes` не должен делать `vec![0; length]` по peer-varint до 2^62 | `ssh3-proto/src/wire.rs:167`, `ssh3-core/src/channel.rs:594` | **Critical** | Кап ≤ 16 MiB (как `util.MaxSSHStringLen`) + потолок на peer-`maxPacketSize`; негативный тест на oversized length |

## 6. Приоритеты функциональности (что НЕ делаем)

| № | Фича Go-версии | Приоритет | Обоснование |
|---|----------------|-----------|-------------|
| 1 | Control master (`-M`/`-S`) | низкий | Большой объём, узкая польза для Rust-ниши |
| 2 | Reverse forwarding (`-R`) | низкий | Нужен только для parity |
| 3 | Proxy jump (`-J`) | низкий | Есть в C-порте, в Rust — нет |
| 4 | X11 forwarding | не делаем | Экзотика |
| 5 | Полный набор Go-фич (~50) | **не делаем** | Цель — второй стек, не замена Go |

**Ядро приоритетов:** M0 → M1 → M2 → M4 → M3 → M7.1/7.2 → M5/M6 → M7.3+.
M5 и M6 идут параллельно M2 (тесты на каждый фикс обязательны).
